QUICK START
  Run apatch from the ROOT OF THE TARGET GIT REPOSITORY, not from the
  installed apatch tool directory. The ZIP must contain
  <repository>/.apatch/params.json and <repository>/source files.

  apatch.sh project-PATCH-feature opSeq=APL,BRN,CHK,STS skipApproves=true
  apatch.sh opSeq=CMT,PSH,PR,MRG,SYN,STS skipApproves=true

WORKFLOW STAGES
  APL  Apply a selected ZIP in the target working tree.
  BRN  Create or safely select the feature branch for the applied patch.
  FMT  Run project-defined MUTATING formatters; optional, before CHK.
  CHK  Run project-defined READ-ONLY checks; required before safe commit.
  REV  Independent script/LLM code review of the checked bytes; optional.
  CMT  Commit confirmed changes without pushing (LOOSE mode).
  PSH  Push the commit; PR creates the pull request.
  MRG  Merge after GitHub checks; SYN synchronizes the local base branch.
  STS  Inspect recorded local workflow state (remote status not queried).
  AUD  Audit local patch history; verifyRemote=true enables GitHub reads.

  Common sequence: APL,BRN,FMT,CHK,REV,CMT,PSH,PR,MRG,SYN,STS.
  Omit FMT if format_commands are absent. Omit REV unless requested or
  review_required=true. STS is safe to run independently.

REUSE AN UNCHANGED ZIP WITH A DIFFERENT FEATURE BRANCH (LOOSE)
  If the branch embedded in the ZIP was already merged, start on a clean,
  current main. This creates a DIFFERENT new branch without repacking:
    apatch.sh original-patch featureBranch=feature/new-work \
      opSeq=APL,BRN,CHK,STS skipApproves=true

  If work continues on an existing feature branch, check it out first.
  The original ZIP may name another branch; prove a matching unfinished
  or verified locally committed predecessor before applying the next ZIP:
    apatch.sh next-patch featureBranch=feature/current-work \
      followup=true opSeq=APL,FMT,CHK,STS skipApproves=true
  Omit FMT when format_commands are not configured; NEVER add BRN for a
  follow-up. These two forms require an explicitly selected new ZIP and
  LOOSE mode. An initial APL-only invocation is also supported; BRN can
  be resumed separately. Existing post-APL, pre-BRN reassignment stays
  available with: apatch.sh op=BRN featureBranch=feature/new-work.

  The selected ZIP, embedded params.json, archive hash and original
  planned-branch identity do NOT change. State and applied history record
  the explicitly selected effective branch. No arbitrary branch switch,
  bypass of base/HEAD/remote checks or duplicate application is allowed.
  featureBranch cannot accompany a legacy JSON, handoffSeq, goal,
  STRICT/FORCE APL or a follow-up containing BRN.

CONFIGURE PROJECT CHECKS AND FORMATTERS
  Create <target-repository>/.apatch/config.yaml with schema_version: 1.
  The checks list is REQUIRED. Examples (adapt paths to your project):

    schema_version: 1
    checks:
      - ["./run-tests.sh"]
      - ["dart", "format", "--output=none", "--set-exit-if-changed", "app/lib", "app/test"]
    format_commands:
      - ["dart", "format", "app/lib", "app/test"]
      - ["cargo", "fmt", "--manifest-path", "core/Cargo.toml", "--all"]
    check_timeout_seconds: 900
    check_idle_timeout_seconds: 30

  Run only installed formatters relevant to your stack; remove commands
  for tools that are not used. All commands are argv arrays, not shell
  strings: no pipes, redirects, glob expansion, or variable interpolation.
  To run a shell pipeline, put it in a project-owned script and list that
  script as one command. Commands execute from the TARGET repository root.

  FMT changes source files and invalidates old CHK/REV evidence. CHK MUST
  NOT change files. If run-tests.sh formats source, split formatting into
  a separate script, then call FMT before CHK. A failed formatter or check
  preserves edits but blocks later publication until corrected.

  Example when the project already has ./run-checks.sh --prepare:
    format_commands:
      - ["./run-checks.sh", "--prepare"]
    checks:
      - ["./run-tests.sh"]

OPTIONAL PREPARATION IN GUARDED MACROS
  prepare_checks: [["./prepare-project.sh"]]
  check_worktree_policy: stop   # or recheck_once
  prepare_checks is NOT the FMT operation. It applies only to guarded
  APPLY_PATCH_CHECK, MERGE, and RUN_ALL macros with planned checks.
  Direct CHK remains strictly read-only, even with recheck_once configured.

OPTIONAL CODE REVIEW (REV)
  Config keys and examples in .apatch/config.yaml:

    review_required: false
    review_timeout_seconds: 180
    review_max_bytes: 131072
    reviewers:
      - id: static
        kind: script
        command: ["./scripts/review.sh", "{diff_file}"]
      - id: gemini
        kind: llm
        model: gemini-2.5-pro
        command: ["gemini", "--model", "{model}", "--output-format", "json", "-p", "Review the supplied diff and return a JSON verdict."]

  Review is OPTIONAL by default. Set review_required: true to block commits
  unless all configured reviewers pass on the current checked snapshot.
  A script reviewer receives the diff on stdin and must exit 0 to pass.
  A model reviewer must return a JSON verdict: PASS, CHANGES_REQUIRED, or
  ESCALATE. The configured external CLI owns authentication and billing.
  Never send private code or secrets to an untrusted external model.

CONFIGURE GLOBAL DEFAULTS
  The installed apatch/apatch.conf uses INI syntax, not YAML. For example:

    [apatch]
    downloads_dir = ~/Downloads
    base_branch = main
    github_timeout_seconds = 30
    github_ci_wait_seconds = 300
    check_timeout_seconds = 900
    check_idle_timeout_seconds = 30

  Project .apatch/config.yaml can override supported global options.
  Never put secrets or credentials in checked-in configuration files.

COMMON COMMANDS AND RESUME
  apatch.sh project-PATCH-new op=APL skipApproves=true
  apatch.sh project-PATCH-new op=3 skipApproves=true
  apatch.sh op=BRN skipApproves=true
  apatch.sh opSeq=FMT,CHK,STS skipApproves=true
  apatch.sh opSeq=CHK,REV,CMT,STS skipApproves=true
  apatch.sh op=STS
  apatch.sh op=AUD verifyRemote=false
  apatch.sh info=PROGRESS
  apatch.sh project-PATCH-new goal=CHECKED planOnly=true
  apatch.sh goal=MERGED skipApproves=true
  apatch.sh project-PATCH-new op=RUN_ALL skipApproves=true

  Named macros: APPLY_PATCH (APL+BRN), APPLY_PATCH_CHECK (through CHK),
  MERGE (CMT through SYN), RUN_ALL (full guarded workflow).
  Goals: CHECKED, COMMITTED, PUSHED, PR_CREATED, MERGED.
  Use handoffSeq=zip1.zip,zip2.zip for multiple explicit APL entries.
  Use followup=true for an explicit new ZIP on a matching LOOSE feature
  branch with pending edits or a verified clean local commit; omit BRN.
  featureBranch=feature/new
  can safely reassign a pending ZIP before BRN where allowed.

  If CHK or REV fails: correct the reported files, run STS, then resume
  from the failed operation. Do not replay APL/BRN on already applied ZIPs
  unless explicitly recovering their state. A previously synchronized ZIP
  with a verified, complete APL-to-SYN opSeq returns ALREADY_COMPLETED and
  displays terminal STS without replaying actions. An incomplete cycle,
  dirty base, or changed remote is not treated as complete.
  If an old params.json lacks a verified ZIP digest, STS reports recorded
  state without trusting that cache. Select the original ZIP explicitly
  to resume: project-PATCH-name opSeq=BRN,CHK,STS skipApproves=true.
  Invalid bounded cache files are preserved in .apatch/backups/ before
  replacement. A symlinked cache or backup directory blocks new APL.
  skipApproves=true disables
  prompts, NOT Git, ZIP, or repository safety checks. FORCE is NOT a
  force-push option. Remote GitHub checks remain separate from local CHK.

VERIFIED ZIP PRODUCTION (SEPARATE FROM CONSUMER OPERATIONS)
  python3 /path/to/apatch/scripts/apatch_preflight.py --project . --prepare
  python3 /path/to/apatch/scripts/apatch_pack.py --help
  Use scripts/apatch_pack.py for source checks and validated ZIP creation before
  applying the ZIP with APL in the destination repository.

BUILD-ONLY VERIFICATION (BLD) AND DEFERRED CHK
  BLD runs build_commands without the canonical checks list. A successful
  build DOES NOT authorize a checked commit or prove that tests passed.
  Builds must not mutate tracked files, Git index, branch or HEAD. BLD
  invalidates previous CHK and REV evidence even when it succeeds.

  In LOOSE, the optional project setting disabled_without_chk determines
  the first action that requires fresh CHK evidence (CMT by default):

    disabled_without_chk: CMT   # CMT, PSH, PR, or MRG

  The explicit equivalent is disabledWithoutChk=MRG for eligible LOOSE
  op/opSeq workflows. Deferring CHK never bypasses review policy, GitHub
  checks or the final exact-commit verification required before MRG.
  A final CHK on an earlier working tree is not proof of final pushed HEAD.

  Example with a configured build_commands list on a continuing feature:
    apatch.sh next-patch opSeq=APL,BLD,CMT,PSH,STS \
      followup=true disabledWithoutChk=MRG skipApproves=true

REVIEW EVIDENCE, CONSENT, RETENTION AND PRIVACY
  Review evidence capture is OFF by default. These optional project YAML
  settings control bounded private review artifacts and consent:

    review_artifacts_enabled: false
    review_artifact_max_bytes: 8388608
    review_context_max_bytes: 32768
    review_context_external_consent: false
    review_context_include_messages: false
    review_context_include_diff: false
    review_retention_enabled: false
    review_retention_max_runs: 100
    review_retention_max_bytes: 536870912
    review_retention_max_age_days: 30

  Structured script reviewers use report_format: apatch-json-v1, enabled
  capture, and scanner entries. Supported scanner formats are ruff-json,
  bandit-json, semgrep-json and sarif-2.1.0. A wrapper returning zero does
  NOT imply that every required scanner succeeded or has no findings.
  A structured-summary LLM reviewer needs explicit external consent,
  enabled capture and valid prior structured scanner evidence. Messages
  and diff excerpts require their own consent-gated include settings.
  Never send source, findings or secrets to an untrusted external model.

  Retention opt-in prunes only independently verified terminal runs under
  a private lock; incomplete, changed or unknown evidence is protected.
  Retrieval, explicit prune preview/deletion and consent-gated summary
  export are INTERNAL Python APIs, not CLI commands or network transfers.
  Review artifacts are never included in handoff ZIPs or ordinary logs.

ADVANCED ACTIONS AND OPTIONS
  Actions 0-14: EXT=0 (exit); BRN=1; BAP=2 (legacy JSON only); APL=3;
  CHK=4; CMT=5; PSH=6; PR=7; MRG=8; SYN=9; STS=10; AUD=11;
  FMT=12; REV=13; BLD=14. Use op=NUMBER, op=CODE or opSeq=CODE,...
  and include terminal STS for a read-only report. AUD runs separately.

  patch=NAME.zip filters read-only STS by archive basename. verifyRemote=true
  applies only to AUD, and permits bounded explicit GitHub reads. STS never
  proves live GitHub status. info=PROGRESS needs no repository or handoff.
  goal=CHECKED|COMMITTED|PUSHED|PR_CREATED|MERGED plans a guarded LOOSE
  session; planOnly=true previews without mutation, and intent=auto|new|
  continue selects the session policy for a goal. Goals and macros are
  distinct from direct op/opSeq operations.

  For multiple ZIPs in one operation sequence, provide a ZIP per APL:
    apatch.sh opSeq=APL,BRN,APL,CHK,STS \
      handoffSeq=first.zip,second.zip skipApproves=true
  This is an explicitly selected LOOSE operation; do not combine
  handoffSeq with followup=true or featureBranch=... . A separate follow-up
  ZIP to an existing feature branch instead uses followup=true and no BRN.

SAFETY AND TROUBLESHOOTING
  ZIP metadata is required at <repository>/.apatch/params.json and may
  specify delete_paths for tracked removals. Unsafe members, symlinks,
  conflicting paths and invalid base/branch/worktree evidence block APL.
  Application is not a multi-file filesystem transaction: an interrupted
  run requires inspection of STS, Git and .apatch/backups/ before retry.
  Do not replay a successful remote mutation after an uncertain result.
  PSH is fast-forward only; PR and MRG check current remote revision,
  reviews, CI and mergeability; SYN is a separate local operation.
  FORCE is recovery only and NEVER performs force-push. skipApproves=true
  skips questions, not validation, review, CHK or GitHub safeguards.
